01 · Le problème

Pourquoi ça ne marche pas en partage de connexion ?

Pour faire « Internet → ton IP publique → Apache sur ton PC », il faut que les connexions entrantes arrivent jusqu'à ton PC. Avec le partage de connexion d'un téléphone, tu ne peux pas créer cette redirection de port toi-même.

Ce qui bloque

  • L'opérateur mobile place souvent le téléphone derrière un CGNAT : l'IP publique est partagée entre de nombreux abonnés.
  • Pas de box à configurer, donc aucune redirection de port possible.
  • Les connexions entrantes vers le port 80 n'atteignent jamais ton PC.

Les solutions

  • Obtenir une connexion mobile avec une IPv4 réellement entrante (option ou APN opérateur adaptés).
  • Utiliser un relais / tunnel externe : le plus simple, et l'objet de ce guide.
02 · Principe

Comment fonctionne un tunnel

Au lieu d'attendre une connexion entrante, c'est ton PC qui ouvre une connexion sortante vers Cloudflare. Cloudflare s'en sert ensuite pour faire passer les visiteurs jusqu'à ton serveur.

Visiteur (Internet) → Réseau Cloudflare → cloudflared (connexion sortante) → Apache / PHP (localhost)

Résultat : aucune redirection de port, aucune box nécessaire, et ta configuration Apache n'est pas modifiée.

Côté pare-feu, cloudflared n'a besoin que de connexions sortantes, notamment vers le port 7844 de Cloudflare. Si un réseau le bloque, le tunnel ne se connecte pas (voir le dépannage).

03 · Installation

Installer cloudflared

Le programme s'appelle cloudflared.exe. Il existe deux façons de l'obtenir sur Windows.

Option 1 : avec winget (recommandé)

winget install --id Cloudflare.cloudflared

Winget place le programme et gère le PATH pour toi. Ferme et rouvre ensuite ton terminal.

Option 2 : téléchargement manuel

Pour un Windows 64 bits (le cas de presque tous les PC), télécharge directement l'exécutable ici :

https://github.com/cloudflare/cloudflared/releases/latest/download/cloudflared-windows-amd64.exe
Pages officielles
  • Page de téléchargement Cloudflare
  • Toutes les versions sur GitHub
Autres fichiers Windows
  • cloudflared-windows-amd64.msi : installeur 64 bits
  • cloudflared-windows-386.exe / .msi : version 32 bits

Le fichier téléchargé s'appelle cloudflared-windows-amd64.exe : renomme-le en cloudflared.exe et range-le dans un dossier fixe, par exemple :

C:\software\serveurs\Cloudflare\cloudflared.exe

Ajoute ensuite ce dossier au PATH de Windows (même méthode que pour PHP, voir le guide Variables d'environnement).

Vérifier l'installation

C:\Users\toi> where cloudflared.exe
C:\software\serveurs\Cloudflare\cloudflared.exe

C:\Users\toi> cloudflared --version

Si where affiche un chemin, le PATH est bon. Sinon, vérifie l'orthographe : c'est cloudflared (avec le « l »), pas coudflared.

04 · Quick Tunnel

Lancer un Quick Tunnel

Le Quick Tunnel est la méthode la plus rapide pour tester : pas de compte, pas de domaine. Tu obtiens une URL publique temporaire en trycloudflare.com.

1

Vérifier que ton serveur répond en local

Ouvre http://localhost dans ton navigateur : ta page doit s'afficher. Sinon, le tunnel n'aura rien à exposer.

2

Ouvrir un nouveau terminal

Un terminal séparé de celui d'Apache ou de PHP : il restera occupé tant que le tunnel tourne.

3

Lancer la commande

cloudflared tunnel --url http://localhost:80

Remplace 80 par le port réel de ton serveur. Avec le serveur intégré de PHP, par exemple php -S localhost:8000, la commande devient cloudflared tunnel --url http://localhost:8000.

4

Copier l'URL affichée

Your quick Tunnel has been created!
https://quelque-chose.trycloudflare.com

Les exemples du genre xxxxx.trycloudflare.com ne sont que des illustrations : utilise l'URL exacte de ton terminal. Le nom est une suite de mots aléatoires placée juste avant .trycloudflare.com.

5

Garder la fenêtre ouverte

L'URL ne fonctionne que tant que le processus cloudflared tourne. Ctrl + C arrête le tunnel, et un nouveau lancement donne une nouvelle URL. Tu ne peux pas choisir le nom d'un Quick Tunnel.

05 · Sécurité

Ce que tu exposes vraiment

Important : toute personne qui connaît l'URL peut accéder à ton serveur local, sans mot de passe. L'URL est aléatoire, mais elle n'est pas secrète : elle peut fuiter (capture d'écran, message partagé, historique).

À ne pas exposer

  • phpMyAdmin ou tout panneau d'administration de base de données.
  • Un fichier .env, des sauvegardes, des fichiers de configuration.
  • Un dossier contenant des documents personnels.
  • Un site avec des identifiants par défaut (admin / admin).

Bonnes pratiques

  • N'expose que le dossier du projet à montrer, pas tout ton disque.
  • Arrête le tunnel (Ctrl + C) dès que le test est fini.
  • Ne partage l'URL qu'aux personnes concernées.
  • Mets un vrai mot de passe sur toute page sensible.

Restreindre l'accès par e-mail

Les versions récentes de cloudflared proposent l'option --allowed-mail : le visiteur doit saisir son e-mail et un code à usage unique reçu par message avant d'accéder au site.

cloudflared tunnel --url http://localhost:80 --allowed-mail alice@example.com

Tu peux répéter l'option pour autoriser plusieurs adresses. Pour changer la liste, il faut arrêter le tunnel et en relancer un nouveau.

06 · Limites

Les limites du Quick Tunnel

Le Quick Tunnel est conçu pour tester et développer, pas pour héberger un site en production.

  • Aucune garantie de disponibilité (pas de SLA).
  • 200 requêtes simultanées maximum : au-delà, les requêtes reçoivent une réponse 429.
  • Pas de Server-Sent Events (SSE).
  • L'URL change à chaque lancement.
  • Un Quick Tunnel ne fonctionne pas si un fichier config.yaml existe déjà dans le dossier .cloudflared de l'utilisateur.

Pour une URL stable et sans ces limites, il faut passer à un tunnel nommé (section 08).

07 · Compatibilité

Apache, PHP et le HTTPS

Le visiteur arrive en HTTPS sur l'URL Cloudflare, mais ton serveur local reçoit du HTTP simple. La plupart des sites statiques ou PHP simples fonctionnent tels quels, mais certains cas demandent un réglage.

Sites qui redirigent vers localhost

Les CMS comme WordPress enregistrent leur adresse dans la base de données. Si cette adresse est http://localhost, les liens, les images et les redirections vont pointer vers ton PC au lieu de l'URL du tunnel : le site paraît cassé pour les visiteurs. Il faut alors adapter l'adresse du site (ou utiliser un tunnel nommé avec un vrai domaine).

Hôtes virtuels Apache

Si tu as plusieurs VirtualHost, Apache choisit le site d'après l'en-tête Host. Avec le tunnel, cet en-tête est celui de l'URL publique et ne correspond à aucun de tes hôtes. Cloudflare prévoit un paramètre d'origine httpHostHeader pour forcer la valeur envoyée à ton serveur local, par exemple le nom de ton hôte virtuel.

ingress:
  - hostname: app.monsite.fr
    service: http://localhost:80
    originRequest:
      httpHostHeader: monsite.local
  - service: http_status:404

Cette forme s'utilise dans le fichier de configuration d'un tunnel nommé. Pour un Quick Tunnel, regarde si une option équivalente existe avec cloudflared tunnel --help.

Serveur intégré de PHP

Rien de spécial : lance php -S localhost:8000 dans un terminal, puis cloudflared tunnel --url http://localhost:8000 dans un autre.

08 · Tunnel nommé

Utiliser son propre domaine

Un tunnel nommé donne une URL stable, sur ton propre nom de domaine, sans les limites du Quick Tunnel.

Prérequis : un compte Cloudflare (gratuit) et un nom de domaine que tu possèdes, ajouté à Cloudflare avec ses serveurs de noms (DNS) pointant vers Cloudflare.
1

Se connecter à Cloudflare

cloudflared tunnel login

Une page s'ouvre dans le navigateur : choisis ton domaine et autorise l'accès. Un fichier cert.pem est créé dans le dossier .cloudflared de ton profil Windows.

2

Créer le tunnel

cloudflared tunnel create mon-tunnel

La commande affiche l'identifiant (UUID) du tunnel et crée un fichier d'identifiants <ID>.json. Garde-le : il donne accès au tunnel.

3

Relier un nom de domaine au tunnel

cloudflared tunnel route dns mon-tunnel app.monsite.fr

Cela crée l'enregistrement DNS qui envoie app.monsite.fr vers ton tunnel.

4

Écrire le fichier config.yml

Crée config.yml dans le dossier .cloudflared de ton profil (par exemple C:\Users\toi\.cloudflared\config.yml) :

tunnel: <ID-DU-TUNNEL>
credentials-file: C:\Users\toi\.cloudflared\<ID-DU-TUNNEL>.json

ingress:
  - hostname: app.monsite.fr
    service: http://localhost:80
  - service: http_status:404

La dernière règle (http_status:404) est obligatoire : elle répond à toute requête qui ne correspond à aucun nom de domaine listé. Tu peux vérifier le fichier avec cloudflared tunnel ingress validate.

5

Lancer le tunnel

cloudflared tunnel run mon-tunnel

Ton site est maintenant accessible sur https://app.monsite.fr, avec le HTTPS géré par Cloudflare.

Alternative : tunnel géré depuis le tableau de bord

Tu peux aussi créer le tunnel directement dans le tableau de bord Cloudflare Zero Trust. Il te fournit alors une commande d'installation prête à copier-coller sur ton PC, et la configuration (domaines, services) se modifie en ligne, sans fichier config.yml.

Attention : une fois un fichier config.yaml présent dans .cloudflared, les Quick Tunnels ne fonctionnent plus sur ce compte Windows. Pour refaire un test rapide, renomme ou déplace temporairement ce fichier.
09 · Service

Lancer cloudflared au démarrage de Windows

Pour que le tunnel nommé démarre tout seul avec Windows, sans fenêtre ouverte, on installe cloudflared comme service Windows. Ouvre un terminal en administrateur.

:: 1. Installer le service
cloudflared.exe service install

:: 2. Créer le dossier de configuration du compte système
mkdir C:\Windows\System32\config\systemprofile\.cloudflared

:: 3. Copier le certificat, le fichier d'identifiants et config.yml
copy C:\Users\%USERNAME%\.cloudflared\cert.pem C:\Windows\System32\config\systemprofile\.cloudflared\cert.pem
copy C:\Users\%USERNAME%\.cloudflared\<ID>.json C:\Windows\System32\config\systemprofile\.cloudflared\<ID>.json
copy C:\Users\%USERNAME%\.cloudflared\config.yml C:\Windows\System32\config\systemprofile\.cloudflared\config.yml

:: 4. Démarrer le service
sc start cloudflared

Dans le config.yml copié, le chemin credentials-file doit pointer vers C:\Windows\System32\config\systemprofile\.cloudflared\<ID>.json, car le service s'exécute avec le compte système et non avec ton utilisateur.

Après toute modification de la configuration, redémarre le service : sc stop cloudflared puis sc start cloudflared.

Commandes utiles

Commande Utilité
cloudflared --version Afficher la version installée

11 · Dépannage

Erreurs fréquentes

  • La commande n'est pas reconnue. Faute de frappe (coudflared), terminal pas rouvert après l'ajout au PATH, ou dossier absent du PATH. Vérifie avec where cloudflared.exe.
  • L'URL ne s'ouvre pas. Tu as probablement copié un exemple (xxxxx) au lieu de l'URL réelle du terminal, ou la fenêtre cloudflared a été fermée.
  • Erreur 502 / « Bad gateway ». Le tunnel fonctionne mais ton serveur local ne répond pas sur ce port : Apache ou php -S est arrêté, ou le port de la commande est mauvais.
  • Erreur 429. Le Quick Tunnel a atteint sa limite de requêtes simultanées. Réduis la charge ou passe à un tunnel nommé.
  • Le tunnel n'arrive pas à se connecter. Certains réseaux (partage de connexion, Wi-Fi public, entreprise) bloquent le protocole par défaut. Force un autre protocole : 
    cloudflared tunnel --protocol http2 --url http://localhost:80
    Vérifie aussi que les connexions sortantes vers le port 7844 ne sont pas filtrées par un pare-feu.
  • Le Quick Tunnel refuse de démarrer. Un fichier config.yaml existe dans le dossier .cloudflared : déplace-le temporairement.
  • Le site s'affiche mal (liens ou images cassés). Ton site est configuré avec l'adresse localhost : voir la section 07.
  • Le service Windows ne démarre pas. Vérifie que cert.pem, le fichier .json et config.yml ont bien été copiés dans le dossier systemprofile\.cloudflared et que les chemins du config.yml sont corrects.
  • Toujours bloqué ? Copie tout ce que cloudflared affiche dans le terminal : ça permet de voir si le souci vient de cloudflared, du serveur local ou de la connexion.
Pour résumer

Quick Tunnel pour tester, tunnel nommé pour durer.

Une commande suffit pour montrer un projet depuis un partage de connexion. Dès que tu veux une adresse stable, ton propre domaine ou un démarrage automatique, passe au tunnel nommé et au service Windows. Dans tous les cas, n'expose que ce que tu veux vraiment rendre public.
