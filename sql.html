01 · Les bases

SQL, c'est quoi exactement ?

SQL signifie Structured Query Language. C'est le langage utilisé pour communiquer avec une base de données relationnelle.

Les 4 grandes familles

  • DQL : lire les données avec SELECT.
  • DML : ajouter ou modifier avec INSERT, UPDATE, DELETE.
  • DDL : créer la structure avec CREATE, ALTER, DROP.
  • TCL : gérer les transactions avec COMMIT et ROLLBACK.

Exemple de table utilisée dans ce cours

CREATE TABLE utilisateurs (
  id INTEGER PRIMARY KEY,
  nom VARCHAR(100),
  email VARCHAR(255),
  age INTEGER,
  ville VARCHAR(100),
  created_at TIMESTAMP
);
Important : il n'existe pas littéralement une liste finie de « toutes les requêtes imaginables ». SQL possède plusieurs dialectes et certaines commandes dépendent du moteur. Cette page rassemble le socle très large qu'un débutant puis un utilisateur intermédiaire doit connaître, avec les combinaisons réellement utiles.
02 · PHP + BDD

Se connecter à une base avec PHP

PHP utilise PDO pour communiquer avec les bases de données. La connexion n'est pas la même avec MySQL et SQLite.

MySQL : connexion à un serveur

Avec MySQL, PHP se connecte à un serveur en indiquant le serveur, la base, l'utilisateur et le mot de passe.

$pdo = new PDO(
    'mysql:host=localhost;dbname=ma_base;charset=utf8mb4',
    'mon_utilisateur',
    'mon_mot_de_passe'
);

À retenir : MySQL fonctionne avec un serveur et un compte utilisateur possédant des droits sur la base.

SQLite : ouvrir un fichier

SQLite ne fonctionne pas comme MySQL. La base est un fichier, par exemple db.sqlite. 

$pdo = new PDO(
    'sqlite:' . __DIR__ . '/db.sqlite'
);

À retenir : il n'y a pas d'identifiant ni de mot de passe SQLite à fournir. PHP ouvre directement le fichier de base de données.

Structure simple pour SQLite

mon-projet/
├── index.php
└── db.sqlite

En production, le fichier SQLite doit idéalement être placé hors du répertoire directement accessible par le serveur web.

03 · PHP + SQL

Exécuter une requête SQL avec PHP

On peut stocker la requête SQL dans une variable puis utiliser une méthode de l'objet PDO pour l'envoyer à la base.

Le principe

$sql = "CREATE TABLE clients (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    nom TEXT NOT NULL
)";

$pdo->exec($sql);

Ici, $sql contient la requête SQL et $pdo->exec() l'envoie à SQLite.

Les principales méthodes PDO

$pdo->exec($sql);
$pdo->query($sql);
$pdo->prepare($sql);
exec() : exécuter une requête qui ne nécessite pas de récupérer des lignes.
query() : exécuter une requête et récupérer un résultat, notamment avec SELECT.
prepare() : préparer une requête avec des paramètres.

Exemple avec SELECT

$sql = "SELECT * FROM clients";

$stmt = $pdo->query($sql);

while ($client = $stmt->fetch(PDO::FETCH_ASSOC)) {
    echo $client['nom'];
}
04 · Sécurité

Sécuriser les requêtes avec les requêtes préparées

Lorsqu'une valeur vient d'un utilisateur, il ne faut pas la concaténer directement dans la requête SQL. Utilise prepare() puis un paramètre.

Méthode avec bindValue()

$sql = "SELECT * FROM clients WHERE id = :id";

$stmt = $pdo->prepare($sql);

$stmt->bindValue(':id', 5, PDO::PARAM_INT);

$stmt->execute();

$client = $stmt->fetch(PDO::FETCH_ASSOC);

:id est un paramètre nommé. bindValue() lui associe la valeur 5 et indique ici qu'il s'agit d'un entier.

Méthode avec execute()

Pour beaucoup de requêtes, cette forme est plus courte et très pratique.

$sql = "SELECT * FROM clients WHERE id = :id";

$stmt = $pdo->prepare($sql);

$stmt->execute([
    'id' => 5
]);

$client = $stmt->fetch(PDO::FETCH_ASSOC);

Exemple avec INSERT

$sql = "INSERT INTO clients (nom, email)
        VALUES (:nom, :email)";

$stmt = $pdo->prepare($sql);

$stmt->execute([
    'nom' => 'Jean',
    'email' => 'jean@example.com'
]);

À retenir : les valeurs variables passent par les paramètres de la requête préparée, pas par une concaténation dans la chaîne SQL.

bindValue() ou execute() ?

bindValue()

Utile lorsque tu veux contrôler explicitement le type du paramètre, par exemple PDO::PARAM_INT.

execute()

Très pratique pour fournir rapidement plusieurs paramètres sous forme de tableau.

Ce qu'il faut éviter

$id = $_GET['id'];

$sql = "SELECT * FROM clients WHERE id = $id";

$pdo->query($sql);

Ne construis pas une requête avec des données utilisateur directement intégrées dans la chaîne SQL. Utilise une requête préparée et ses paramètres.

05 · DQL

SELECT : récupérer des données

C'est la commande la plus utilisée. Elle sert à lire une ou plusieurs colonnes.

SELECT simple

Récupère toutes les colonnes.

SELECT * FROM utilisateurs;

À retenir : * signifie « toutes les colonnes ».

Choisir certaines colonnes

SELECT nom, email
FROM utilisateurs;

Plus propre et souvent plus performant que récupérer inutilement toutes les données.

WHERE : filtrer

SELECT *
FROM utilisateurs
WHERE age >= 18;
= égal
<> ou != différent
>, <, >=, <=
AND, OR, NOT

AND, OR et parenthèses

SELECT *
FROM utilisateurs
WHERE age >= 18
  AND ville = 'Bordeaux';

SELECT *
FROM utilisateurs
WHERE (ville = 'Bordeaux' OR ville = 'Paris')
  AND age >= 18;

LIKE : rechercher du texte

-- Commence par Jean
SELECT * FROM utilisateurs
WHERE nom LIKE 'Jean%';

-- Contient "martin"
SELECT * FROM utilisateurs
WHERE nom LIKE '%martin%';

-- Un caractère quelconque
WHERE nom LIKE 'J_an';

% représente zéro ou plusieurs caractères. _ représente généralement un seul caractère.

IN, BETWEEN et NULL

SELECT * FROM utilisateurs
WHERE ville IN ('Bordeaux', 'Paris', 'Lyon');

SELECT * FROM utilisateurs
WHERE age BETWEEN 18 AND 30;

SELECT * FROM utilisateurs
WHERE email IS NULL;

DISTINCT, ORDER BY, LIMIT et OFFSET

SELECT DISTINCT ville
FROM utilisateurs
ORDER BY ville ASC;

SELECT *
FROM utilisateurs
ORDER BY age DESC
LIMIT 10
OFFSET 20;

Cas concret : pagination. Ici on saute 20 résultats puis on en récupère 10.

CASE : créer une condition dans le résultat

SELECT
  nom,
  age,
  CASE
    WHEN age < 18 THEN 'Mineur'
    WHEN age >= 65 THEN 'Senior'
    ELSE 'Adulte'
  END AS categorie
FROM utilisateurs;
06 · DML

INSERT, UPDATE et DELETE

INSERT : ajouter une ligne

INSERT INTO utilisateurs (nom, email, age, ville)
VALUES ('Marie Dupont', 'marie@example.com', 28, 'Bordeaux');

Toujours préciser les colonnes est une bonne habitude.

INSERT multiple

INSERT INTO utilisateurs (nom, email, age)
VALUES
  ('Paul', 'paul@example.com', 31),
  ('Sarah', 'sarah@example.com', 26),
  ('Lucas', 'lucas@example.com', 42);

INSERT ... SELECT

INSERT INTO utilisateurs_archive (nom, email)
SELECT nom, email
FROM utilisateurs
WHERE age > 80;

UPDATE : modifier

UPDATE utilisateurs
SET ville = 'Périgueux'
WHERE id = 5;

-- Modifier plusieurs colonnes
UPDATE utilisateurs
SET nom = 'Marie Martin',
    age = 29
WHERE id = 5;

Attention : un UPDATE sans WHERE peut modifier toutes les lignes.

DELETE : supprimer des lignes

DELETE FROM utilisateurs
WHERE id = 5;

Attention : DELETE sans WHERE supprime toutes les lignes de la table.

UPSERT : insérer ou mettre à jour

La syntaxe varie selon le moteur.

-- PostgreSQL / SQLite moderne
INSERT INTO utilisateurs (email, nom)
VALUES ('marie@example.com', 'Marie')
ON CONFLICT (email)
DO UPDATE SET nom = EXCLUDED.nom;

-- MySQL / MariaDB : syntaxe courante
INSERT INTO utilisateurs (email, nom)
VALUES ('marie@example.com', 'Marie')
ON DUPLICATE KEY UPDATE nom = 'Marie';
07 · Relations

JOIN : relier plusieurs tables

Imaginons utilisateurs et commandes, avec commandes.utilisateur_id qui pointe vers l'utilisateur.

INNER JOIN

SELECT u.nom, c.id, c.total
FROM utilisateurs u
INNER JOIN commandes c
  ON c.utilisateur_id = u.id;

Retourne uniquement les lignes ayant une correspondance des deux côtés.

LEFT JOIN

SELECT u.nom, c.id
FROM utilisateurs u
LEFT JOIN commandes c
  ON c.utilisateur_id = u.id;

Garde tous les utilisateurs, même ceux qui n'ont aucune commande.

RIGHT JOIN et FULL OUTER JOIN

-- RIGHT JOIN : dépend du moteur
SELECT *
FROM utilisateurs u
RIGHT JOIN commandes c
  ON c.utilisateur_id = u.id;

-- FULL OUTER JOIN : PostgreSQL / SQL Server notamment
SELECT *
FROM utilisateurs u
FULL OUTER JOIN commandes c
  ON c.utilisateur_id = u.id;

SELF JOIN

-- Un employé possède un manager dans la même table
SELECT e.nom AS employe,
       m.nom AS manager
FROM employes e
LEFT JOIN employes m
  ON e.manager_id = m.id;
08 · Calculer

COUNT, SUM, AVG, MIN, MAX et GROUP BY

SELECT
  COUNT(*) AS nombre_utilisateurs,
  AVG(age) AS age_moyen,
  MIN(age) AS plus_jeune,
  MAX(age) AS plus_age
FROM utilisateurs;

-- Compter par ville
SELECT ville, COUNT(*) AS total
FROM utilisateurs
GROUP BY ville
HAVING COUNT(*) >= 10
ORDER BY total DESC;

WHERE filtre les lignes avant le regroupement. HAVING filtre les groupes après GROUP BY.

09 · DDL

Créer et modifier la structure

CREATE DATABASE et CREATE TABLE

CREATE DATABASE mon_site;

CREATE TABLE produits (
  id INTEGER PRIMARY KEY,
  nom VARCHAR(150) NOT NULL,
  prix DECIMAL(10,2) NOT NULL,
  stock INTEGER DEFAULT 0,
  actif BOOLEAN DEFAULT TRUE
);

ALTER TABLE

-- Ajouter une colonne
ALTER TABLE produits
ADD COLUMN description TEXT;

-- Modifier dépend du moteur SQL
-- Exemple PostgreSQL
ALTER TABLE produits
ALTER COLUMN nom TYPE VARCHAR(250);

-- Renommer une colonne
ALTER TABLE produits
RENAME COLUMN nom TO titre;

DROP, TRUNCATE et différences

-- Supprime les données et la table
DROP TABLE produits;

-- Vide rapidement la table, conserve sa structure
TRUNCATE TABLE produits;

-- DELETE conserve aussi la structure et peut filtrer
DELETE FROM produits
WHERE actif = FALSE;
10 · Intégrité

Les contraintes

CREATE TABLE commandes (
  id INTEGER PRIMARY KEY,
  utilisateur_id INTEGER NOT NULL,
  numero VARCHAR(50) UNIQUE,
  total DECIMAL(10,2) CHECK (total >= 0),
  statut VARCHAR(20) DEFAULT 'en_attente',
  FOREIGN KEY (utilisateur_id)
    REFERENCES utilisateurs(id)
    ON DELETE CASCADE
);
PRIMARY KEY : identifiant unique.
FOREIGN KEY : relation entre tables.
NOT NULL : valeur obligatoire.
UNIQUE : pas de doublon.
DEFAULT : valeur par défaut.
CHECK : règle de validation.
11 · Performance

INDEX, VIEW et EXPLAIN

-- Index
CREATE INDEX idx_utilisateurs_email
ON utilisateurs(email);

-- Index unique
CREATE UNIQUE INDEX idx_email_unique
ON utilisateurs(email);

-- Supprimer un index : syntaxe selon le moteur
DROP INDEX idx_utilisateurs_email;

Un index accélère certaines recherches, avec un coût en stockage et lors des écritures.

-- Vue : requête enregistrée
CREATE VIEW utilisateurs_adultes AS
SELECT id, nom, email
FROM utilisateurs
WHERE age >= 18;

SELECT * FROM utilisateurs_adultes;
-- Comprendre le plan d'exécution
EXPLAIN
SELECT *
FROM utilisateurs
WHERE email = 'marie@example.com';
12 · Transactions

Transactions : COMMIT et ROLLBACK

BEGIN;

UPDATE comptes
SET solde = solde - 100
WHERE id = 1;

UPDATE comptes
SET solde = solde + 100
WHERE id = 2;

COMMIT;

-- En cas de problème
ROLLBACK;

Une transaction permet de traiter plusieurs opérations comme un ensemble cohérent.

13 · Niveau avancé

Sous-requêtes, CTE et fonctions fenêtre

Sous-requête

SELECT nom, age
FROM utilisateurs
WHERE age > (
  SELECT AVG(age)
  FROM utilisateurs
);

EXISTS

SELECT u.*
FROM utilisateurs u
WHERE EXISTS (
  SELECT 1
  FROM commandes c
  WHERE c.utilisateur_id = u.id
);

CTE avec WITH

WITH clients_importants AS (
  SELECT utilisateur_id, SUM(total) AS chiffre
  FROM commandes
  GROUP BY utilisateur_id
)
SELECT *
FROM clients_importants
WHERE chiffre > 1000;

UNION et UNION ALL

-- UNION retire les doublons
SELECT email FROM clients
UNION
SELECT email FROM prospects;

-- UNION ALL conserve les doublons
SELECT email FROM clients
UNION ALL
SELECT email FROM prospects;

Fonctions fenêtre : ROW_NUMBER, RANK

SELECT
  nom,
  ville,
  ROW_NUMBER() OVER (
    PARTITION BY ville
    ORDER BY age DESC
  ) AS position
FROM utilisateurs;

Les fonctions fenêtre calculent un résultat sur un groupe sans écraser les lignes comme GROUP BY.

CTE récursive

WITH RECURSIVE arbre AS (
  SELECT id, parent_id, nom
  FROM categories
  WHERE parent_id IS NULL

  UNION ALL

  SELECT c.id, c.parent_id, c.nom
  FROM categories c
  JOIN arbre a ON c.parent_id = a.id
)
SELECT * FROM arbre;
