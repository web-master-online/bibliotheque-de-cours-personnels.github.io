01 · Le projet

Ce qu'on va construire

On va lire ensemble un petit jeu écrit en langage C, qui tourne dans la console Windows (l'invite de commandes). Tu diriges un # qui doit éviter des X qui descendent le long de la piste.

Ce que fait le jeu

  • Tu déplaces le # vers la gauche ou la droite avec les flèches du clavier.
  • Des obstacles X descendent depuis le haut de l'écran.
  • Si un X touche ton #, c'est perdu.
  • Le score monte avec le temps, et le jeu devient de plus en plus difficile.
  • Échap quitte la partie.

À quoi ressemble l'écran

|                            |
|   XX           X           |
|                            |
|                            |
|                     XX     |
|                            |
|                            |
|        X                   |
|                            |
|             #              |
Score : 42
Fleches gauche/droite, Echap pour quitter

Le vrai jeu affiche 25 lignes ; ici seulement 10 pour l'exemple. Le # est tout en bas, les X descendent vers lui.

Ce que tu vas apprendre

  • Les variables et les types (int, char).
  • Les tableaux à deux dimensions (la piste est une grille).
  • Les fonctions : découper un programme en petites tâches.
  • Les boucles (for, while) et les conditions (if).
  • Les nombres aléatoires (placer les obstacles au hasard).
  • La lecture du clavier en direct, sans bloquer le jeu.
Pas besoin de savoir programmer. Chaque mot est expliqué. Garde le code complet (dernière section) sous la main pour suivre.
02 · Préparer

Compiler et lancer le jeu

Un programme en C s'écrit dans un fichier texte. Un compilateur le transforme ensuite en programme exécutable (un fichier .exe sous Windows).

1

Enregistrer le code

Copie le code complet dans un fichier nommé jeu.c.

2

Avoir un compilateur

Il t'en faut un : par exemple GCC (via MinGW-w64 ou MSYS2), ou un environnement comme Code::Blocks ou Visual Studio. Pour vérifier que GCC est installé, tape gcc --version dans un terminal : une version doit s'afficher.

Si la commande n'est pas reconnue, ajoute le dossier de GCC au PATH de Windows : voir le guide Variables d'environnement.

3

Compiler puis lancer

gcc jeu.c -o jeu.exe
jeu.exe

gcc jeu.c -o jeu.exe signifie « compile jeu.c et crée le programme jeu.exe ». Ensuite, jeu.exe lance le jeu.

Windows uniquement : ce code utilise conio.h et windows.h, qui n'existent que sous Windows. Sous Linux ou macOS, la compilation s'arrête avec une erreur du type « conio.h: No such file or directory ».
03 · Vue d'ensemble

Le plan du programme

Avant d'entrer dans le détail, voici comment le jeu est organisé.

Le principe : une boucle qui tourne en continu

Un jeu vidéo, même très simple, répète sans arrêt les mêmes étapes, environ 50 fois par seconde. Chaque passage s'appelle une frame (une image).

1. Lire le clavier→2. Mettre à jour le jeu→3. Tester la collision→4. Dessiner l'écran→5. Faire une pause→↻ On recommence

C'est cette boucle qui fait vivre le jeu : même si tu n'appuies sur aucune touche, la piste continue d'avancer.

Les fonctions du programme

Le code est découpé en fonctions : chacune fait une seule petite tâche.

FonctionSon rôle
allerADéplacer le curseur à un endroit précis de la console
cacherCurseurCacher le petit curseur clignotant
creerLigneFabriquer une ligne de la piste (bords + obstacles au hasard)
initialiserCartePréparer la piste de départ (vide)
defilerFaire avancer la piste d'une ligne
dessinerAfficher la piste, le joueur et le score
mainLe point de départ du programme : contient la boucle de jeu

Anatomie d'une fonction

void allerA(int x, int y)
{
    /* ... instructions ... */
}
  • void : ce que la fonction renvoie. Ici « rien » : elle fait son travail sans rendre de résultat.
  • allerA : le nom de la fonction.
  • (int x, int y) : les paramètres, c'est-à-dire les valeurs qu'on lui donne pour travailler (ici deux nombres entiers).
  • { ... } : le corps, les instructions exécutées quand on appelle la fonction.

Pour utiliser une fonction, on l'appelle par son nom : allerA(0, 0);.

Le compilateur lit le fichier de haut en bas. Une fonction doit donc être écrite avant l'endroit où on s'en sert. C'est pour cela que main, qui utilise toutes les autres, est tout en bas.

04 · Les bases

Les #include et les constantes

Le début du fichier prépare le terrain : les outils dont on a besoin, puis les valeurs fixes du jeu.

Les #include : les boîtes à outils

#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <time.h>
#include <conio.h>    /* _getch() et _kbhit() */
#include <windows.h>  /* curseur et Sleep() */

Une ligne #include dit au compilateur : « va chercher cette boîte à outils, j'ai besoin de ses fonctions ».

FichierCe qu'il apporteUtilisé pour
stdio.hprintf, fputsAfficher du texte
stdlib.hrand, srand, systemNombres aléatoires et commande cls
string.hmemcpyCopier des morceaux de mémoire
time.htimeLire l'heure (pour initialiser le hasard)
conio.h_getch, _kbhitLire le clavier en direct
windows.hSleep, curseur de la consoleFonctions propres à Windows

Tout ce qui est écrit entre /* ... */ est un commentaire : le compilateur l'ignore, il est là pour les humains.

Les constantes avec #define

#define LARGEUR   30
#define HAUTEUR   25
#define BORD      '|'
#define VIDE      ' '
#define OBSTACLE  'X'
#define JOUEUR    '#'

#define NOM valeur donne un nom à une valeur. Avant de compiler, Windows remplace partout le nom par la valeur. Il n'y a ni = ni ; sur ces lignes.

NomValeurSignification
LARGEUR30Nombre de colonnes de la piste, bords compris
HAUTEUR25Nombre de lignes de la piste
BORD'|'Le caractère des murs
VIDE' 'Une case libre (un espace)
OBSTACLE'X'Un obstacle
JOUEUR'#'Le joueur

Pourquoi des constantes ? Pour lire == OBSTACLE plutôt qu'un mystérieux == 'X', et pour pouvoir tout modifier à un seul endroit.

Les apostrophes 'X' désignent un seul caractère. Les guillemets "texte" désignent un texte.

05 · Les données

La carte : un tableau à deux dimensions

Toute la piste est stockée dans une seule variable : un tableau en forme de grille.

La déclaration

/* La carte : carte[y][x], la ligne 0 est en haut de l'écran.
   Le joueur n'est PAS stocké dedans : il est dessiné par-dessus. */
char carte[HAUTEUR][LARGEUR];

Lis-la ainsi : « une variable nommée carte, qui contient HAUTEUR lignes de LARGEUR caractères ».

  • char : un type de variable qui contient un caractère.
  • Un tableau est une rangée de cases numérotées. À deux dimensions, c'est une grille.
  • On lit une case avec carte[y][x] : d'abord la ligne (y), puis la colonne (x).
  • La numérotation commence à 0 : les lignes vont de 0 à 24 et les colonnes de 0 à 29. La ligne 0 est en haut, et y augmente en descendant.
  • C'est une variable globale : elle est déclarée en dehors de toute fonction, donc toutes les fonctions peuvent la lire et la modifier.
        x=0   x=1   x=2   ...  x=28  x=29
y=0      |     .     .    ...    .     |
y=1      |     .     X    ...    .     |
 ...
y=24     |     .     .    ...    .     |

Les points représentent des cases vides.

Le joueur n'est pas dans la carte

Le commentaire le dit : le joueur n'est pas stocké dans carte, il est dessiné par-dessus au moment de l'affichage.

  • Quand le joueur bouge, il n'y a rien à effacer dans la carte.
  • La case sous le joueur contient toujours ce qu'il y a vraiment sur la piste. Si c'est un X, on sait qu'il y a collision.
06 · L'écran

Les fonctions de la console : allerA et cacherCurseur

Ces deux petites fonctions préparent l'écran. Elles utilisent des outils fournis par Windows.

allerA() : se placer à un endroit de l'écran

void allerA(int x, int y)
{
    COORD pos;
    pos.X = (SHORT)x;
    pos.Y = (SHORT)y;
    SetConsoleCursorPosition(GetStdHandle(STD_OUTPUT_HANDLE), pos);
}

Quand on utilise printf, le texte s'écrit à la suite du précédent et la console défile vers le bas. Dans un jeu, on veut au contraire redessiner toujours au même endroit. allerA place le curseur (l'endroit où le prochain texte s'écrira) à la colonne x et à la ligne y.

  • COORD pos; : crée une variable pos de type COORD, un type Windows qui regroupe deux nombres, X et Y (on parle de *structure*).
  • pos.X = (SHORT)x; : on range x dans pos.X. Le (SHORT) convertit le nombre entier int dans le type attendu par Windows.
  • GetStdHandle(STD_OUTPUT_HANDLE) : récupère l'accès à la sortie de la console, c'est-à-dire l'écran.
  • SetConsoleCursorPosition(..., pos) : déplace le curseur aux coordonnées pos.

Dans la console, le coin en haut à gauche est la position (0, 0).

cacherCurseur() : masquer le curseur clignotant

void cacherCurseur(void)
{
    CONSOLE_CURSOR_INFO info;
    info.dwSize = 1;
    info.bVisible = FALSE;
    SetConsoleCursorInfo(GetStdHandle(STD_OUTPUT_HANDLE), &info);
}
  • void entre parenthèses : cette fonction ne prend aucun paramètre.
  • CONSOLE_CURSOR_INFO info; : une structure qui décrit l'aspect du curseur.
  • info.dwSize = 1; : l'épaisseur du curseur, en pourcentage de la case. Windows exige une valeur entre 1 et 100, même quand on cache le curseur.
  • info.bVisible = FALSE; : le curseur devient invisible.
  • SetConsoleCursorInfo(..., &info) : applique ces réglages à la console.

Sans cette fonction, le curseur clignoterait en sautant partout à chaque redessin de l'écran.

07 · La piste

Fabriquer la piste : creerLigne et initialiserCarte

Ces deux fonctions construisent les lignes de la piste.

creerLigne() : fabriquer une ligne

/* Fabrique une ligne : des bords à gauche et à droite, du vide au milieu,
   et éventuellement des obstacles placés au hasard */
void creerLigne(int y, int avecObstacles, int densite)
{
    int x;

    carte[y][0] = BORD;
    carte[y][LARGEUR - 1] = BORD;

    for (x = 1; x < LARGEUR - 1; x++) {
        carte[y][x] = VIDE;
    }

    if (avecObstacles) {
        for (x = 1; x < LARGEUR - 1; x++) {
            /* densite = chance en % qu'une case devienne un obstacle */
            if (rand() % 100 < densite) {
                carte[y][x] = OBSTACLE;
            }
        }
    }
}

Elle reçoit trois paramètres : y (quelle ligne fabriquer), avecObstacles (1 si on veut des obstacles, 0 sinon) et densite (le pourcentage de chance d'obstacle par case).

  1. int x; : un compteur, déclaré au début de la fonction (c'est le style du C classique).
  2. On pose les bords : carte[y][0] est la première case (colonne 0) et carte[y][LARGEUR - 1] la dernière (colonne 29).
  3. La boucle for (x = 1; x < LARGEUR - 1; x++) se lit : « pars de x = 1, continue tant que x < 29, et après chaque tour fais x++ (ajoute 1) ». Elle parcourt donc toutes les cases entre les bords, qu'on remplit avec VIDE.
  4. if (avecObstacles) : en C, 0 veut dire faux et toute autre valeur veut dire vrai.
  5. rand() % 100 < densite : rand() donne un grand nombre aléatoire ; % 100 en garde le reste de la division par 100, donc un nombre entre 0 et 99. Si ce nombre est plus petit que densite (par exemple 10), la case devient un obstacle : c'est 10 chances sur 100, soit 10 %.

Chaque case est tirée au sort séparément : avec 10 %, une ligne de 28 cases contient en moyenne environ 3 obstacles.

initialiserCarte() : la piste de départ

/* Au départ : une piste vide pour laisser le temps au joueur */
void initialiserCarte(void)
{
    int y;

    for (y = 0; y < HAUTEUR; y++) {
        creerLigne(y, 0, 0);
    }
}

Au lancement du jeu, on remplit les 25 lignes avec creerLigne(y, 0, 0) : des bords, du vide, aucun obstacle. Le joueur a ainsi un peu de temps avant les premiers dangers.

for (y = 0; y < HAUTEUR; y++) parcourt les lignes de 0 à 24.

08 · Le défilement

defiler() : faire avancer la piste

C'est la fonction la plus importante du jeu : c'est elle qui donne l'impression que la piste avance.

Le code

/* LE DÉFILEMENT : chaque ligne prend la place de celle du dessous.
   On part du BAS vers le HAUT, sinon on écraserait les lignes
   avant de les avoir copiées. La ligne du bas disparaît,
   et on crée une nouvelle ligne tout en haut. */
void defiler(int avecObstacles, int densite)
{
    int y;

    for (y = HAUTEUR - 1; y > 0; y--) {
        memcpy(carte[y], carte[y - 1], LARGEUR);
    }
    creerLigne(0, avecObstacles, densite);
}

L'idée

Pour faire avancer la piste, on décale toutes les lignes d'un cran vers le bas, la dernière ligne disparaît, et on fabrique une nouvelle ligne tout en haut. Exemple avec 4 lignes :

Avant

ligne 0 : A
ligne 1 : B
ligne 2 : C
ligne 3 : D

Après

ligne 0 : NOUVELLE
ligne 1 : A
ligne 2 : B
ligne 3 : C   (D a disparu)

Comme la piste descend vers le joueur (placé en bas), on a l'impression qu'il avance.

Ligne par ligne

  • for (y = HAUTEUR - 1; y > 0; y--) : on démarre tout en bas (ligne 24) et on remonte : y-- retire 1 à chaque tour, et on s'arrête avant la ligne 0.
  • memcpy(carte[y], carte[y - 1], LARGEUR); : memcpy(destination, source, taille) copie taille octets. Ici, la ligne y reçoit une copie de la ligne y - 1, celle du dessus. carte[y] seul désigne toute la ligne, et LARGEUR caractères = une ligne complète.
  • creerLigne(0, avecObstacles, densite); : on fabrique la nouvelle ligne du haut. Les deux paramètres sont simplement transmis à creerLigne.

Pourquoi du bas vers le haut ?

Si on copiait du haut vers le bas, on écraserait les lignes avant de les avoir copiées :

Mauvais ordre (de haut en bas)
ligne 1 = ligne 0   ->  la ligne 1 devient A  (B est perdue)
ligne 2 = ligne 1   ->  la ligne 2 devient A  (on recopie ce qu'on vient d'écraser)
ligne 3 = ligne 2   ->  la ligne 3 devient A

Résultat : toutes les lignes deviennent des copies de A

En partant du bas, chaque ligne est copiée avant d'être remplacée :

yOpérationEffet
3ligne 3 ← ligne 2D disparaît, C descend
2ligne 2 ← ligne 1B descend
1ligne 1 ← ligne 0A descend
—creerLigne(0, ...)Une nouvelle ligne apparaît en haut
09 · L'affichage

dessiner() : afficher le jeu

Cette fonction affiche toute la piste, le joueur, le score et les instructions.

Le code

/* Redessine tout l'écran sans l'effacer (on revient juste en haut à gauche),
   ce qui évite le clignotement */
void dessiner(int joueurX, int joueurY, int score)
{
    char ligne[LARGEUR + 2];
    int y;

    allerA(0, 0);
    for (y = 0; y < HAUTEUR; y++) {
        memcpy(ligne, carte[y], LARGEUR);
        if (y == joueurY) {
            ligne[joueurX] = JOUEUR;
        }
        ligne[LARGEUR] = '\n';
        ligne[LARGEUR + 1] = '\0';
        fputs(ligne, stdout);
    }
    printf("Score : %d     \n", score);
    printf("Fleches gauche/droite, Echap pour quitter");
}

Pas à pas

  1. allerA(0, 0); : on revient en haut à gauche de l'écran et on réécrit par-dessus l'image précédente. Effacer tout l'écran à chaque frame le ferait clignoter ; réécrire au même endroit évite ce défaut.
  2. char ligne[LARGEUR + 2]; : un tableau temporaire de 32 cases : les 30 caractères de la ligne, plus un retour à la ligne \n et un marqueur de fin \0.
  3. for (y = 0; y < HAUTEUR; y++) : on traite les 25 lignes une par une.
  4. memcpy(ligne, carte[y], LARGEUR); : on copie la ligne de la carte dans le tableau temporaire.
  5. if (y == joueurY) { ligne[joueurX] = JOUEUR; } : si c'est la ligne du joueur, on pose le # dans la copie, jamais dans la carte elle-même.
  6. ligne[LARGEUR] = '\n'; ligne[LARGEUR + 1] = '\0'; : on ajoute le retour à la ligne, puis le \0. En C, un texte est un tableau de caractères qui se termine par \0 : sans lui, fputs ne saurait pas où s'arrêter.
  7. fputs(ligne, stdout); : affiche le texte à l'écran (stdout = la sortie standard). Contrairement à puts, fputs n'ajoute pas de retour à la ligne, d'où le \n ajouté à la main.
  8. printf("Score : %d \n", score); : %d est remplacé par la valeur de score. Les espaces à la fin effacent d'éventuels restes de l'image précédente.
  9. Le dernier printf affiche les instructions, sans retour à la ligne : au prochain tour, allerA(0, 0) nous ramène en haut de toute façon.

joueurX, joueurY et score sont des paramètres : les variables de main sont locales (les autres fonctions ne les voient pas), il faut donc les transmettre. carte, elle, est globale et reste visible partout.

10 · Le programme principal

main() : les variables et le démarrage

main est le point de départ : c'est la première fonction exécutée quand le programme se lance.

Les variables

int joueurX = LARGEUR / 2;
int joueurY = HAUTEUR - 2;

Le démarrage

srand((unsigned)time(NULL));
system("cls");
cacherCurseur();
initialiserCarte();
  • srand((unsigned)time(NULL)); : initialise le hasard. time(NULL) donne le nombre de secondes écoulées depuis 1970, un nombre différent à chaque lancement. Sans cette ligne, rand() produirait la même suite à chaque partie : les obstacles seraient toujours aux mêmes endroits.
  • system("cls"); : efface la console. On ne le fait qu'une fois, au départ.
  • cacherCurseur(); : masque le curseur clignotant.
  • initialiserCarte(); : prépare la piste vide.
11 · Le cœur du jeu

La boucle de jeu, étape par étape

Tout se passe dans une boucle while. Elle répète ses instructions tant que enJeu vaut 1.

Le squelette

while (enJeu) {
    /* 1) ENTREES */
    /* 2) MISE A JOUR */
    /* 3) COLLISION */
    /* 4) AFFICHAGE */
    /* 5) PAUSE */
}

Chaque tour de boucle est une frame. L'ordre est important : on lit d'abord ce que veut le joueur, on fait évoluer le jeu, on vérifie le résultat, on affiche, puis on attend.

1

Les entrées : lire le clavier

/* 1) ENTRÉES : _kbhit() dit s'il y a une touche en attente,
      sans bloquer. S'il n'y en a pas, on continue quand même. */
while (_kbhit()) {
    touche = _getch();
    if (touche == 27) {
        enJeu = 0;
    } else if (touche == 0 || touche == 224) {
        touche = _getch();
        /* Les bords bloquent, comme les murs du premier jeu */
        if (touche == 75 && carte[joueurY][joueurX - 1] != BORD) {
            joueurX--;
        }
        if (touche == 77 && carte[joueurY][joueurX + 1] != BORD) {
            joueurX++;
        }
    }
}
  • _kbhit() répond à la question : « y a-t-il une touche en attente ? ». Il ne bloque pas : s'il n'y en a pas, le jeu continue. C'est ce qui fait tourner le jeu tout seul. Avec scanf, le programme resterait figé en attendant que tu appuies.
  • _getch() lit la touche sans l'afficher et sans attendre la touche Entrée. On ne l'appelle que quand _kbhit() a confirmé qu'une touche attend.
  • while (_kbhit()) (et non un simple if) vide toutes les touches en attente d'un coup.
  • touche == 27 : le code de la touche Échap. On met enJeu à 0 : la boucle s'arrêtera.
  • Les flèches envoient deux codes : d'abord 0 ou 224 (« une touche spéciale arrive »), puis le vrai code. D'où le deuxième _getch(). || veut dire « ou ».
  • 75 = flèche gauche, 77 = flèche droite. && veut dire « et » : on avance si c'est la bonne touche et que la case voisine n'est pas un BORD.
  • joueurX-- retire 1 à joueurX (c'est la même chose que joueurX = joueurX - 1) ; joueurX++ ajoute 1.

Les obstacles ne bloquent pas le déplacement : tu peux marcher dedans. C'est l'étape 3 qui te fera perdre.

2

La mise à jour : faire évoluer le jeu

/* 2) MISE À JOUR : la map n'avance pas à chaque frame,
      seulement toutes les "vitesse" frames */
frame++;
if (frame % vitesse == 0) {
    score++;

    /* Des obstacles une ligne sur trois, pour laisser des passages */
    if (score % 3 == 0) {
        avecObstacles = 1;
    } else {
        avecObstacles = 0;
    }
    defiler(avecObstacles, densite);

    /* Ça devient plus dur avec le temps */
    if (score % 100 == 0 && vitesse > 2) {
        vitesse--;
    }
    if (score % 150 == 0 && densite < 30) {
        densite = densite + 3;
    }
}
  • frame++ : un tour de plus.
  • frame % vitesse == 0 : % donne le reste d'une division. Avec vitesse = 8, c'est vrai aux tours 8, 16, 24… La piste n'avance donc qu'une fois sur 8, alors que le clavier est lu à chaque tour : le joueur réagit instantanément.
  • score++ : le score compte le nombre d'avancées de la piste.
  • score % 3 == 0 : une ligne sur trois contient des obstacles (avecObstacles = 1). Les deux autres sont vides, ce qui laisse des passages.
  • defiler(avecObstacles, densite) : on fait avancer la piste.
  • Tous les 100 points, vitesse baisse de 1 (la piste accélère) jusqu'à un minimum de 2. Tous les 150 points, densite monte de 3 (plus d'obstacles) tant qu'elle est inférieure à 30, donc elle s'arrête à 31 %.

Les premiers obstacles apparaissent en haut quand le score atteint 3, puis descendent jusqu'à la ligne du joueur : il a environ 3 à 4 secondes de calme au début.

3

La collision : tester si on a perdu

/* 3) COLLISION : un obstacle ne bloque pas, il fait perdre */
if (carte[joueurY][joueurX] == OBSTACLE) {
    perdu = 1;
    enJeu = 0;
}

Comme le joueur n'est pas stocké dans carte, la case carte[joueurY][joueurX] contient ce qu'il y a sous lui. Si c'est un OBSTACLE, on met perdu à 1 et enJeu à 0 : la boucle s'arrête.

Ce test est fait à chaque tour, donc il détecte aussi bien un X sur lequel tu marches qu'un X que la piste amène sur ta ligne.

4

L'affichage

/* 4) AFFICHAGE */
dessiner(joueurX, joueurY, score);

On appelle dessiner en lui donnant la position du joueur et le score.

5

La pause

/* 5) PAUSE : environ 50 frames par seconde */
Sleep(20);

Sleep(20) met le programme en pause pendant 20 millisecondes. 1000 ms ÷ 20 ms = environ 50 frames par seconde. Sans cette pause, la boucle tournerait des milliers de fois par seconde : le processeur serait saturé et le jeu bien trop rapide. Avec vitesse = 8, la piste avance environ 6 fois par seconde ; avec vitesse = 2, environ 25 fois.

12 · La fin

Après la boucle : la fin de partie

Quand enJeu passe à 0, la boucle se termine et le programme exécute la fin de main.

Le code

allerA(0, HAUTEUR + 3);
if (perdu) {
    printf("PERDU ! Score final : %d\n", score);
    printf("Appuie sur une touche pour quitter...");
    Sleep(800);
    while (_kbhit()) {
        _getch();   /* on vide les touches restées en attente */
    }
    _getch();
}
printf("\n");
return 0;
  • allerA(0, HAUTEUR + 3); : on se place sous l'affichage (25 lignes de piste, plus le score, plus les instructions), en laissant une ligne vide.
  • if (perdu) : le message n'apparaît que si on a perdu. Si tu as quitté avec Échap, on passe directement à la fin.
  • Sleep(800); : une pause de 0,8 seconde, pour que tu aies le temps de voir ce qui s'est passé même si tu étais en train de marteler les flèches.
  • while (_kbhit()) { _getch(); } : on vide les touches restées en attente, sinon l'une d'elles fermerait le message instantanément.
  • _getch(); : cette fois on attend vraiment une touche, pour que la fenêtre ne se ferme pas toute seule.
  • return 0; : termine main et le programme. Le 0 signifie « tout s'est bien passé ».
13 · À toi de jouer

Aller plus loin et problèmes fréquents

Défis pour t'entraîner

  1. Change LARGEUR et HAUTEUR : le jeu s'adapte tout seul.
  2. Change les caractères : par exemple #define JOUEUR '@'.
  3. Rends le jeu plus facile ou plus difficile en modifiant vitesse et densite au départ.
  4. Ajoute un meilleur score : une variable meilleurScore, comparée au score à la fin de la partie.
  5. Autorise le déplacement vers le haut et le bas : les flèches haut et bas ont pour codes 72 et 80. Attention à ne pas sortir de la piste !
  6. Ajoute un bonus (par exemple un +) qui donne des points quand on le touche.

Problèmes fréquents

  • gcc n'est pas reconnu : le dossier de GCC n'est pas dans le PATH (voir le guide Variables d'environnement).
  • conio.h: No such file or directory : tu n'es pas sous Windows. Ce code ne fonctionne que sous Windows.
  • L'écran clignote : vérifie que dessiner commence par allerA(0, 0) et n'efface pas tout l'écran avec system("cls").
  • Les obstacles sont toujours les mêmes : la ligne srand(...) est absente ou a été supprimée.
  • Le jeu est trop rapide ou trop lent : joue sur Sleep(20) et sur vitesse.
  • Les flèches ne répondent pas : vérifie le test touche == 0 || touche == 224 et les codes 75 et 77.
14 · Le code complet

Le code complet du jeu

Voici l'ensemble du programme, prêt à être copié dans jeu.c.

Afficher le code complet
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <time.h>
#include <conio.h>    /* _getch() et _kbhit() */
#include <windows.h>  /* curseur et Sleep() */

#define LARGEUR   30
#define HAUTEUR   25
#define BORD      '|'
#define VIDE      ' '
#define OBSTACLE  'X'
#define JOUEUR    '#'

/* La carte : carte[y][x], la ligne 0 est en haut de l'écran.
   Le joueur n'est PAS stocké dedans : il est dessiné par-dessus. */
char carte[HAUTEUR][LARGEUR];

void allerA(int x, int y)
{
    COORD pos;
    pos.X = (SHORT)x;
    pos.Y = (SHORT)y;
    SetConsoleCursorPosition(GetStdHandle(STD_OUTPUT_HANDLE), pos);
}

void cacherCurseur(void)
{
    CONSOLE_CURSOR_INFO info;
    info.dwSize = 1;
    info.bVisible = FALSE;
    SetConsoleCursorInfo(GetStdHandle(STD_OUTPUT_HANDLE), &info);
}

/* Fabrique une ligne : des bords à gauche et à droite, du vide au milieu,
   et éventuellement des obstacles placés au hasard */
void creerLigne(int y, int avecObstacles, int densite)
{
    int x;

    carte[y][0] = BORD;
    carte[y][LARGEUR - 1] = BORD;

    for (x = 1; x < LARGEUR - 1; x++) {
        carte[y][x] = VIDE;
    }

    if (avecObstacles) {
        for (x = 1; x < LARGEUR - 1; x++) {
            /* densite = chance en % qu'une case devienne un obstacle */
            if (rand() % 100 < densite) {
                carte[y][x] = OBSTACLE;
            }
        }
    }
}

/* Au départ : une piste vide pour laisser le temps au joueur */
void initialiserCarte(void)
{
    int y;

    for (y = 0; y < HAUTEUR; y++) {
        creerLigne(y, 0, 0);
    }
}

/* LE DÉFILEMENT : chaque ligne prend la place de celle du dessous.
   On part du BAS vers le HAUT, sinon on écraserait les lignes
   avant de les avoir copiées. La ligne du bas disparaît,
   et on crée une nouvelle ligne tout en haut. */
void defiler(int avecObstacles, int densite)
{
    int y;

    for (y = HAUTEUR - 1; y > 0; y--) {
        memcpy(carte[y], carte[y - 1], LARGEUR);
    }
    creerLigne(0, avecObstacles, densite);
}

/* Redessine tout l'écran sans l'effacer (on revient juste en haut à gauche),
   ce qui évite le clignotement */
void dessiner(int joueurX, int joueurY, int score)
{
    char ligne[LARGEUR + 2];
    int y;

    allerA(0, 0);
    for (y = 0; y < HAUTEUR; y++) {
        memcpy(ligne, carte[y], LARGEUR);
        if (y == joueurY) {
            ligne[joueurX] = JOUEUR;
        }
        ligne[LARGEUR] = '\n';
        ligne[LARGEUR + 1] = '\0';
        fputs(ligne, stdout);
    }
    printf("Score : %d     \n", score);
    printf("Fleches gauche/droite, Echap pour quitter");
}

int main(void)
{
    int joueurX = LARGEUR / 2;
    int joueurY = HAUTEUR - 2;
    int score = 0;
    int frame = 0;
    int vitesse = 8;     /* la map défile toutes les "vitesse" frames */
    int densite = 10;    /* % de chance d'obstacle par case */
    int enJeu = 1;
    int perdu = 0;
    int touche;
    int avecObstacles;

    srand((unsigned)time(NULL));
    system("cls");
    cacherCurseur();
    initialiserCarte();

    /* LA BOUCLE DE JEU : elle tourne en continu, même sans touche appuyée */
    while (enJeu) {

        /* 1) ENTRÉES : _kbhit() dit s'il y a une touche en attente,
              sans bloquer. S'il n'y en a pas, on continue quand même. */
        while (_kbhit()) {
            touche = _getch();
            if (touche == 27) {
                enJeu = 0;
            } else if (touche == 0 || touche == 224) {
                touche = _getch();
                /* Les bords bloquent, comme les murs du premier jeu */
                if (touche == 75 && carte[joueurY][joueurX - 1] != BORD) {
                    joueurX--;
                }
                if (touche == 77 && carte[joueurY][joueurX + 1] != BORD) {
                    joueurX++;
                }
            }
        }

        /* 2) MISE À JOUR : la map n'avance pas à chaque frame,
              seulement toutes les "vitesse" frames */
        frame++;
        if (frame % vitesse == 0) {
            score++;

            /* Des obstacles une ligne sur trois, pour laisser des passages */
            if (score % 3 == 0) {
                avecObstacles = 1;
            } else {
                avecObstacles = 0;
            }
            defiler(avecObstacles, densite);

            /* Ça devient plus dur avec le temps */
            if (score % 100 == 0 && vitesse > 2) {
                vitesse--;
            }
            if (score % 150 == 0 && densite < 30) {
                densite = densite + 3;
            }
        }

        /* 3) COLLISION : un obstacle ne bloque pas, il fait perdre */
        if (carte[joueurY][joueurX] == OBSTACLE) {
            perdu = 1;
            enJeu = 0;
        }

        /* 4) AFFICHAGE */
        dessiner(joueurX, joueurY, score);

        /* 5) PAUSE : environ 50 frames par seconde */
        Sleep(20);
    }

    allerA(0, HAUTEUR + 3);
    if (perdu) {
        printf("PERDU ! Score final : %d\n", score);
        printf("Appuie sur une touche pour quitter...");
        Sleep(800);
        while (_kbhit()) {
            _getch();   /* on vide les touches restées en attente */
        }
        _getch();
    }
    printf("\n");
    return 0;
}
Pour résumer

Un jeu, c'est une boucle qui lit, met à jour, teste, dessine et attend.

Tout le reste n'est que de la préparation : une grille pour la piste, des fonctions pour la fabriquer, la faire avancer et l'afficher. Une fois cette structure comprise, tu peux la réutiliser pour presque n'importe quel petit jeu en console.
